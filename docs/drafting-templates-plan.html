How we organise a 75-template library

At 15 templates a flat Notices / Orders / Approvals / Letters grouping works. At 75 it doesn't — the "Notices" pile becomes unusable. The fix: group by the officer's function, with category as a secondary tag.

  • Add a group field to each template — the function it belongs to (Assessment, Reassessment, Penalty, Recovery, TDS, Exemptions, Transfer Pricing & DRP, Appeals & Revision, Investigation, I&CI / e-Verification, Prosecution).
  • The Drafting page shows collapsible function sections, the officer's own function expanded first (we already know the wing), the rest collapsed — so a TRO sees Recovery open, an AO sees Assessment open.
  • Category becomes an icon/tag (Notice · Show-cause · Order · Approval · Certificate · Summons · Letter) inside each group, not the top-level split.
  • Search stays (already there) for jumping straight to "148A" or "garnishee".
Backend: the ranking logic already tags each template with wings; adding a group label and grouping in the UI is a small change shipped alongside Batch 2, so the growing library stays navigable from the first big tranche.

Ground rules baked into every template

  • Current law only — reassessment on the FA-2024 §148A(1)/(3) flow; penalty 270A for AY 2017-18+ (271(1)(c) legacy); 12AB (not 12AA); stay-of-demand's 20% guideline.
  • Correctly wing-tagged — each template surfaces first for its function's officers; nothing hidden (soft emphasis).
  • Grounded, never invented — the drafting engine uses only the figures/dates/names the officer enters; it writes "[not on record]" for anything missing, exactly like the order engine.
  • A CA validation pass is worth doing on the section sub-clauses once the full set is in — this plan is our best reading of the Act, verified against public sources.
